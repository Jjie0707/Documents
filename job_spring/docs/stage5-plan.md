# 阶段 5 · 招聘截图识别与调用限额：小任务计划

2026-10-27，用户确认阶段 4 验收完毕，要求先介绍并细分阶段 5。本轮只核对代码、记录验收和拆分任务，没有开始阶段 5 实现，没有调用模型或改数据库。

## 目标与已核对的基础

目标流程：选择一张招聘截图 → 校验图片 → 检查并预占额度 → 调用视觉模型 → 校验结构化结果 → 展示可编辑草稿 → 用户确认保存 → 岗位详情。

识别本身不创建岗位；用户不保存则没有新的岗位记录。识别失败或额度不足时，手动新增与编辑始终可用。沿用登录、用户隔离、CSRF、原 package 职责和逐任务验收方式；不做批量截图、长期图片存储、自动投递或阶段 6 部署。

已核对：

- JobApplication、JobResponse 和既有 SQL 已有十个目标字段：公司、岗位名、城市、薪资、岗位职责、任职要求、学历、来源平台、原始链接、截止日期。
- CreateJobRequest、UpdateJobRequest、两个写 Service 及 JobCreateView/JobEditView 目前只接收/写入前四项；其余字段在详情中已有展示。必须先补全手动保存，避免识别结果无法修改或落库。
- 当前 pom.xml 尚无 Redis 依赖，也没有 vision 业务实现。真实服务商、模型、图片限制、全站额度数值和所需配置将在相关任务开工时确定；不在规划中臆造已完成状态或最新产品规格。

## 开发顺序：10 个小任务 + 1 次整体验收

| 编号 | 小任务 | 交付与验收重点 |
| --- | --- | --- |
| 5.1 | 手动新增/编辑支持岗位职责和任职要求 | API 与两处表单一起接通；可保存多行文本、回读、修改和清空，原四字段与其他岗位保持正确。 |
| 5.2 | 手动新增/编辑支持其余四项 | 学历、来源平台、原始链接、截止日期；明确长度、链接及日期规则，空值语义和身份隔离，详情正确回读。 |
| 5.3a | 基础截图选择、预览与上传校验 | 单张 PNG/JPEG、浏览器预览/替换/移除、后端真实格式/大小/像素校验。非法文件不调用模型、不扣额度，不长期保存图片。 |
| 5.3b | Windows/macOS 的上传增强 | 在基础选择入口上增加图片拖拽和主动粘贴截图，统一进入同一校验流程；Windows Ctrl+V、macOS Command+V 按实际浏览器验收。 |
| 5.3c | iOS/Android 的上传适配 | 从相册/文件选图，支持时提供拍照入口并保留选图回退；核对 HEIC/HEIF、照片方向、长截图及超大图，完成真机验收。 |
| 5.4 | 识别草稿契约与结果校验 | 为十字段定义独立 DTO/校验规则；识别不确定的字段留空，处理缺字段、错误类型、无效日期、超长文本、异常 JSON；不让模型返回值直接成为数据库实体。以隔离测试验证，不增加面向用户的假识别结果或临时测试接口。 |
| 5.5 | Redis 每日额度查询与页面展示 | 接入配置，GET /api/vision/quota；显示当前 IP 每日额度、可用状态和重置时间。查询不扣次数，Redis 不可用时识别不可用，手动录入可用。 |
| 5.6 | 原子扣额与全站每日上限 | 使用统一服务原子检查/预占 IP 与全站两种额度，处理日期过期和并发；验证非法图片不扣、超额不调用，客户端不能随意伪造 IP。先用受控测试客户端验证，不产生真实模型调用。 |
| 5.7 | 真实视觉模型接入与识别结果页面 | 在既有校验与额度控制后调用模型，POST /api/vision/extract 返回经校验的草稿；页面展示真实结果，先不保存。基本超时、错误提示、重复点击保护和关闭开关从首次接入就具备。 |
| 5.8 | 识别结果预填与确认保存 | 用户主动将草稿填入可编辑岗位表单，检查修改后点击保存，复用岗位创建 API；处理现有草稿覆盖、取消、重识别与保存结果不确定，未经确认不自动保存、不悄悄覆盖已有岗位。 |
| 5.9 | 阶段 5 整体验收 | 贯通识别到保存；集中回归无内容/部分识别/模型异常、超额/Redis 故障、登录和 CSRF、用户隔离及手机体验，确保手动录入不受影响。 |

有页面的任务尽量同时交付 API 与 UI；5.4、5.6 侧重后端规则与有意义的自动测试，不额外暴露测试入口，也不新增 HTTP 文件。每个任务完成后解释关键 Java 文件、方法和执行顺序，更新文档，等待用户验收再推进。

## 岗位字段与跨设备边界（2026-10-27 用户补充）

- 新字段同时进入原新增/编辑 API、表单、回读和详情，不仅供识别使用。公司/岗位名继续必填，其余字段选填；不为旧记录编造缺失内容。
- 识别和手动录入共用可编辑字段。截图没有招聘 URL 或明确截止日期等信息时留空；来源平台也只在可确定时填入，不能根据品牌名拼造链接。
- 一套 Vue 网页与 Java 上传接口，按浏览器能力增强，不按四种操作系统各写一套后端。选择文件是基础入口，粘贴/拖拽/拍照均复用同一校验、预览和上传流程。
- 具体平台/浏览器、图片格式及验收矩阵见[跨设备补充](stage5-research.md)。无法实测的设备必须标为待验收，窄屏截图不等于真机文件选择、相机或剪贴板验证。
- 原 5.3 细分为 5.3a/5.3b/5.3c，仍一次只实现并验收其中一步；其余任务顺序保持。

## 额度与模型接入约定

沿用开发方案：每 IP 每天默认 5 次、可配置，同时有全站每日上限。建议统一使用上海自然日及清晰的重置时间，具体配置在额度任务确认。

- 先完成登录、CSRF 和图片校验，再在即将调用模型时原子预占两类额度；校验失败不扣。
- 真实请求已发出但模型超时或响应异常时，不能假设供应商未计费，也不能自动重发；失败是否返还额度应在 5.6/5.7 明确定义，不能静默放宽。建议按已发出的调用计次、默认不自动返还；本轮只是建议，尚未实现。
- Redis 故障不绕过限额调用模型；模型开关未启用或配置不完整时明确提示不可用。
- 原始 IP 不进入长期业务记录；按既有方案考虑服务端 HMAC 标识，代理 IP 仅信任配置的来源。账号级额外限额不是本阶段必做项。
- 模型与额度配置只在服务端；密钥放被忽略的本机配置或服务器环境，不粘贴到文档、前端、日志或 Git。不读取/输出不必要的私密配置。
- 服务商和模型尚未最终选定。2026-10-27 按用户要求查阅官方资料，优先评估免费视觉模型 GLM-4.6V-Flash；官方能力与免费说明已核对，尚无账号凭证下的真实调用结果。详见[免费模型与跨设备补充](stage5-research.md)。接入前再次核对接口、图片约束、JSON 能力、账号实际限流与费用；本轮没有发送招聘图片或进行模型调用。

## 推荐先做 5.1

目标只开放 responsibilities 和 requirements 两个字段的新增/编辑，沿用现有岗位写入流程。

主要文件：CreateJobRequest、UpdateJobRequest、JobCreateService、JobUpdateService、JobCreateView.vue、JobEditView.vue 及相关岗位测试。JobApplication/JobResponse 已有字段，详情已能显示，不预设需要改表或重构。
