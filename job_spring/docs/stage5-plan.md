## 目标与规划时核对的基础（5.1 实施前）

目标流程：选择一张招聘截图 → 校验图片 → 检查并预占额度 → 调用视觉模型 → 校验结构化结果 → 展示可编辑草稿 → 用户确认保存 → 岗位详情。

识别本身不创建岗位；用户不保存则没有新的岗位记录。识别失败或额度不足时，手动新增与编辑始终可用。沿用登录、用户隔离、CSRF、原 package 职责和逐任务验收方式；不做批量截图、长期图片存储、自动投递或阶段 6 部署。

已核对：

- JobApplication、JobResponse 和既有 SQL 已有十个目标字段：公司、岗位名、城市、薪资、岗位职责、任职要求、学历、来源平台、原始链接、截止日期。
- CreateJobRequest、UpdateJobRequest、两个写 Service 及 JobCreateView/JobEditView 目前只接收/写入前四项；其余字段在详情中已有展示。必须先补全手动保存，避免识别结果无法修改或落库。
- 开工前基线曾无 Redis/vision；现已实现图片检查、草稿校验和 Redis 额度查询。当前默认每 IP 每天 5 次、上海自然日；全站上限和可信代理配置在 5.6 确定，模型仍在 5.7。

## 额度与模型接入约定

沿用开发方案：每 IP 每天默认 5 次、可配置，同时有全站每日上限。建议统一使用上海自然日及清晰的重置时间，具体配置在额度任务确认。

- 先完成登录、CSRF 和图片校验，再在即将调用模型时原子预占两类额度；校验失败不扣。
- 真实请求已发出但模型超时或响应异常时，不能假设供应商未计费，也不能自动重发；失败是否返还额度应在 5.6/5.7 明确定义，不能静默放宽。建议按已发出的调用计次、默认不自动返还；本轮只是建议，尚未实现。
- Redis 故障不绕过限额调用模型；模型开关未启用或配置不完整时明确提示不可用。
- 原始 IP 不进入长期业务记录；按既有方案考虑服务端 HMAC 标识，代理 IP 仅信任配置的来源。账号级额外限额不是本阶段必做项。
- 模型与额度配置只在服务端；密钥放被忽略的本机配置或服务器环境，不粘贴到文档、前端、日志或 Git。不读取/输出不必要的私密配置。
- 服务商和模型尚未最终选定。2026-10-27 按用户要求查阅官方资料，优先评估免费视觉模型 GLM-4.6V-Flash；官方能力与免费说明已核对，尚无账号凭证下的真实调用结果。详见[免费模型与跨设备补充](stage5-research.md)。接入前再次核对接口、图片约束、JSON 能力、账号实际限流与费用；本轮没有发送招聘图片或进行模型调用。
