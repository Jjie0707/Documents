## 正式库只读校验（已通过）

为减少重复粘贴和人工逐位比较，新增可复用的[校验 SQL](sql/stage6_migration_verify.sql)与 [Mac 校验脚本](../scripts/verify-mysql-migration.zsh)，文件中不含实际记录、密码或备份摘要。

在 Mac 本机执行脚本，分别连接原 MySQL 9.3 数据源和通过 SSH 13306 转发的 Linux MySQL 8.4 正式 job_tracker 库。两次认证均由 mysql 客户端在本机提示输入密码；源库账号和端口交互输入，Linux 暂用 root 只读检查，因为专用账号尚未获得正式库权限。

SQL 只修改本次连接的会话设置并执行只读事务，不使用全局设置、DDL 或业务写入。采用 REPEATABLE READ 与一致性快照读取，仍依赖源库暂停写入及 DDL 暂停的约定，不能让两台服务器在同一时刻建立跨库事务。参考 [MySQL 只读事务与一致性快照](https://dev.mysql.com/doc/refman/8.4/en/commit.html)。

每端输出 22 行元数据：

- 1 行连接身份信息：实际版本和所选库名，强制源为 9.3、目标为 8.4，数据库为正式 job_tracker；防止两次误连同一端或误用临时库。
- 7 行结构签名：表/引擎/排序规则/自增序列、字段定义、索引、约束及启用状态、约束列顺序、外键规则与 CHECK 表达式。不比较物理大小、统计基数等随环境变化的字段。
- 4 行内容签名：按 ID 排序，对四表全部字段（本次结构合计 41 列）分层 SHA-256；只输出表名、数量和摘要，不输出实际用户名、密码哈希值或业务正文。JSON 序列化区分 NULL 和空字符串。
- 10 行完整性检查：正式库名、缺失/额外表、额外对象、外键检查开关、三项归属关联、状态和轮次值合法性；所有异常数必须为 0，即使两端相同也不放行非零异常。

客户端 --show-warnings 会将每条语句的警告写入私有结果，脚本按完整行数和字段格式识别并拒绝额外警告/异常输出，同时拒绝截断或损坏的摘要。group_concat_max_len 仅在会话内提高到 1 MiB，以便完整计算当前数据集摘要。若未来数据规模超过限制，将停止而非把截断结果判为成功。

结果自动存入仓库外新建的私有目录。脚本验证两端版本和所有完整性项后，排除预期不同的版本行，逐字节比较其余 21 项；只打印通过/失败、四表数量和私有结果位置，不打印摘要。失败时保留现场、源库继续冻结，不重导、不切换。
