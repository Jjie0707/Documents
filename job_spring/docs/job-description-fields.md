## 接口和内容规则

沿用 `POST /api/jobs` 和 `PUT /api/jobs/{id}`，两者的开放字段由四个扩展为六个：

| 字段 | 必填 | 上限（Unicode 码点） |
| --- | --- | --- |
| companyName | 是 | 200 |
| jobTitle | 是 | 200 |
| city | 否 | 100 |
| salary | 否 | 100 |
| responsibilities | 否 | 10,000 |
| requirements | 否 | 10,000 |

DTO 紧凑构造器先调用 `strip()` 去除首尾空白，空串转为 `null`，再执行 `@Valid`。正文内部换行、缩进和特殊字符保留，不截断超长文本。两项均按纯文本处理，不渲染 HTML。

**PUT 提交完整六字段目标值。所有选填项省略、null 或空白都表示清空，不表示保持原值。** 旧的四字段 PUT 仍能被接收，但会清空职责和要求；调用方需要更新为六字段提交。当前网页已同步，保存其他字段时会携带预填的职责和要求。

学历、来源平台、原始链接和截止日期尚未开放写入；更新时不出现在 SET 中，已有值保留。状态继续通过独立 PATCH 接口修改。主键、用户归属和初始状态仍由后端决定。不存在和越权继续统一返回 404。

实体、JobResponse、SQL 和详情展示原本已有两项字段，本次无需改表、执行初始化 SQL、新增依赖或新增 HTTP 文件。未连接用户 MySQL 核实实际结构；不能把仓库 SQL 当成已核实的本机结构。

## 执行顺序和关键后端文件

```text
新增页输入六字段 / 编辑页 GET 详情后预填六字段
  → 前端必填和码点长度提示
  → 既有 api.js 获取 CSRF Token，POST / PUT JSON + 会话 Cookie
  → Security 校验登录和 CSRF
  → CreateJobRequest / UpdateJobRequest 构造并规范化字符串
  → @Valid 执行最终字段校验
  → Controller 从登录身份获取 currentUserId
  → JobCreateService.createForUser / JobUpdateService.updateForUser
  → JobMapper 写入；编辑后按 ID + 当前用户回读
  → JobResponse 返回；页面进入详情并 GET 回读
```

- `job/common/CreateJobRequest.java` 和 `UpdateJobRequest.java`：新增两个 String 分量及 `@CodePointLength(max = 10000)`，沿用独立请求 DTO、首尾规范化和 toString 脱敏。Java 的 String.length() 计算 UTF-16 单元，不能用来替代码点长度；本次测试覆盖 10,000 个 emoji 能保存、10,001 个被拒绝。每项最多约 40,000 个 UTF-8 字节，为现有 utf8mb4 TEXT 留有容量余量。
- `job/service/JobCreateService.java` 的 `createForUser`：在事务内显式调用 `setResponsibilities` 和 `setRequirements`，再 `mapper.insert(job)`。只把允许的内容字段复制到实体，客户端不能指定归属或初始状态。
- `job/service/JobUpdateService.java` 的 `updateForUser`：继续使用 `LambdaUpdateWrapper`，新增 `.set(JobApplication::getResponsibilities, request.responsibilities())` 和 requirements 对应一行。显式 set 即使值为 null 也会写 SQL NULL，避免实体更新默认跳过空值，使“清空”有效。
- UPDATE 自身带 `id` 与 `userId` 两个条件，随后用 `JobReadService.findForUser` 按同样条件回读。事务覆盖更新和回读；同值重复更新仍成功，不用影响行数等于 0 判断 404。现有最后写入者覆盖的并发约定继续保留，本次没有新增乐观锁。
- Controller、Mapper、JobResponse、JobReadService 和 advice 可直接复用。字段错误通过原有 fields 返回，错误响应不回显正文或数据库异常。

## 必要前端数据流

`JobCreateView.vue`、`JobEditView.vue` 的 form 和 inputs 都扩展为六字段；新两项使用 textarea，桌面各占整行，700px 及以下仍单列。表单按码点计数，不使用 maxlength 静默截断。

编辑的预填与 hasChanges 遍历同一份 inputs，避免只改职责或要求时保存按钮未启用。null 显示为空字符串。保存前两项都是草稿；取消不发送 PUT，保存期间由原 fieldset 一并禁用，字段错误仍能聚焦 textarea。连接失败、超时或响应解析失败沿用原不确定状态，暂停继续提交，再用“重新加载已保存信息”核对。重新加载会替换草稿。

详情原有文本插值和 `white-space: pre-wrap` 继续展示换行；没有新增页面路由或修改 API/CSRF 封装。
