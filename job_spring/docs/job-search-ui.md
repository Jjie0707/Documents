## 必要的数据流与学习点

```text
进入列表 → GET /api/jobs → 显示全部岗位
输入关键词草稿 → 点击搜索或回车 → 检查去空白后的字符数
  → 保存本次提交条件 → URLSearchParams 编码 keyword
  → GET /api/jobs?keyword=...
  → Java 按当前用户 + 关键词查询
  → 成功后显示岗位、数量及本次关键词
清空搜索 → GET /api/jobs → 恢复全部岗位
```

1. **区分输入、提交和成功结果。** keyword 是输入框草稿，submittedKeyword 是最近提交条件，
   appliedKeyword 是成功返回结果对应的条件。输入框改了但没有提交时，列表仍标明旧结果对应的关键词。
   查询失败时显示已提交条件，“重新加载”重复该条件，不会悄悄把新草稿当成一次搜索提交。
2. **编码由 URLSearchParams 负责。** 不直接拼接用户输入，避免 +、&、% 改变查询参数含义。
   只调用既有 request 发 GET，不获取 CSRF Token、不发送 JSON。最终字段校验、SQL 绑定、LIKE 转义和用户归属
   仍由已验收的 Java 接口负责，前端校验只负责及时提示。
3. **长度按 Unicode 码点检查。** [...value].length 避免将补充字符算成两个字符；去首尾空白后最多 100。
   超长不发请求，aria-invalid 与错误提示关联并聚焦输入；Java 仍保留最终校验。
4. **新旧请求分开。** 相同条件加载中暂时禁用搜索并在函数入口防重；输入新关键词或清空时可以发新请求。
   请求编号递增，只有当前编号可更新岗位、错误和 loading，旧响应晚到也不能覆盖新结果。
   离开列表时使旧编号失效，避免旧请求更新页面或因旧 401 跳转登录。
5. **无匹配与失败不同。** 成功且关键词非空、结果为空时显示“没有匹配的岗位”；全部列表为空时保留原“还没有岗位记录”。
   请求失败隐藏旧结果，显示错误和重试，不将失败伪装成 0 条匹配。401 清除页面身份并转登录。
   400 字段错误在输入处显示，成功重试后清除旧字段提示；只有当前草稿仍等于请求关键词时才关联该字段错误。

本次关键词仅保存在当前列表组件中，刷新、离开列表后再返回时恢复全部岗位，不写浏览器存储或 URL。
输入框自带的清除图标只修改草稿，仍需点击搜索或“清空搜索”才更新列表。
当前接口返回完整匹配数组，数量为本次结果条数，分页与状态筛选尚未实现。
