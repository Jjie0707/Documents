## 接口约定与范围

`DELETE /api/jobs/{id}`，要求当前登录会话和有效 CSRF Token，不需要请求体。
路径 ID 决定删除目标，用户 ID 只从 Security 当前登录身份取得；查询参数或 JSON 不能切换用户或目标。

本次沿用数据库草案的**物理删除**：直接删除 job_applications 中的记录，没有回收站或恢复接口。
只删除当前用户指定的这一条岗位，不改用户账号、其他岗位，也不执行面试数据级联删除。
现有数据库草案通过外键 ON DELETE RESTRICT 阻止删除有关联面试记录的岗位。
该限制继续由数据库原子地检查，不先读取子记录数量再决定是否删除，避免检查与删除之间的并发空隙。

| HTTP 状态 | 含义 |
| --- | --- |
| 204 | 成功删除一条岗位，响应体为空，Cache-Control: no-store |
| 400 | 路径 ID 非整数或超出 Long 范围 |
| 401 | 未登录且 CSRF 检查已通过 |
| 403 | CSRF Token 缺失或无效；未登录也可能先返回此状态 |
| 404 | 岗位不存在、已经删除或属于其他用户，三者响应一致 |
| 409 | 关联数据或完整性约束阻止删除，岗位与关联记录保留 |
| 503 | 其他数据库访问失败，只返回通用提示 |

业务错误沿用 code、message、fields 结构，删除无表单字段，fields 为空对象。
Security 的 401/403 沿用既有结构，不返回原始输入、数据库连接信息、约束名称或底层异常。
204 没有 JSON，客户端不能无条件调用 response.json()。

## 执行顺序与关键代码

```text
DELETE 路径 + 会话 Cookie + CSRF Token
  → Security 检查登录与 CSRF
  → JobDeleteController：将路径解析为 Long，从 AppUserDetails 取当前用户 ID
  → JobDeleteService：在事务内执行带归属条件的 DELETE
  → JobMapper：执行一条 SQL，数据库同时检查外键约束
  → 删除 1 条：Controller 返回 ResponseEntity<Void>、204 空响应
  → 删除 0 条：抛出 404；约束异常：409；其他数据库异常：503
```

- `controller/JobDeleteController.java` 使用 @DeleteMapping。没有要接收的业务字段，无需为删除单独创建请求 DTO。
  ResponseEntity<Void> 表示成功不返回岗位对象；删除之后再读取详情自然会找不到。
- `service/JobDeleteService.java` 复用现有 JobMapper，通过 LambdaQueryWrapper 构造删除条件。
  getter 方法引用用于定位字段；没有直接调用只按主键删除的 deleteById。
- `advice/JobDeleteExceptionHandler.java` 只作用于新 Controller。DataIntegrityViolationException 是
  DataAccessException 的子类，Spring 优先选择更具体的处理方法，分别返回 409 和 503。
- `@Transactional` 延续已有业务方法的事务边界。当前核心写操作只有一条 SQL，本身已是原子操作；
  事务与外键不等于自动恢复或级联删除，代码没有捕获异常后继续删除子记录。

实际执行的 SQL 等价于：

```sql
DELETE FROM job_applications
WHERE id = ? AND user_id = ?;
```

归属条件必须出现在 DELETE 本身，不能只靠前端隐藏按钮，也不能先查归属后再做不带归属的删除。
因为 id 是主键，该语句最多删除一条记录，不存在批量删除入口。

**本次可以用影响行数 0 判断未找到。** DELETE 返回本次实际删除的记录数：0 就表示没删到目标。
这与之前 UPDATE 不同：UPDATE 写入相同值时也可能返回 0，但岗位仍存在，因此编辑接口需要按归属回读。

重复删除第一次为 204，之后为 404，但最终数据库状态始终是目标岗位不存在；幂等不要求每次 HTTP 状态相同。
发生 409 时数据库拒绝删除，岗位和子记录都保留。发生连接中断或响应丢失时，客户端仍需通过 GET 核对结果，
不能仅凭没收到 204 就断定删除没有发生。
普通 DELETE 不消耗 CSRF Token，登录或退出后仍需重新获取当前会话 Token。
