## 目标、文件与数据流

在新增岗位页已有截图区域增加拖入单张本地图片、聚焦后 Ctrl+V / Command+V 主动粘贴图片。保留选择文件回退，三种入口共用预览、替换、移除、体积检查与主动上传，不改变十字段手动表单。

- `frontend/src/screenshot-input.js`：将三种入口的数据整理为同一个 File 或明确错误；不读取文字、HTML 或图片链接。
- `frontend/src/components/ScreenshotUploadPanel.vue`：接收 drag/drop/paste 事件、显示拖入提示，复用原 Blob URL 预览与检查状态；挂载/卸载时注册/清理区域外文件拖入的默认导航保护。
- `frontend/tests/screenshot-input.test.js`：12 项输入规则回归，无新增依赖。
- 原 Java Controller/Service、api.js、岗位页面保存逻辑和数据库本轮均未修改。

```text
选择 / drop 的本地文件 / 截图区域内主动 paste 的图片
  → selectSingleScreenshot：恰好一张、非空、最多 5 MiB
  → receiveSelection：废弃旧请求结果、撤销旧 Blob URL、建立新预览
  → 用户点击检查
  → 原 postMultipart 获取 CSRF、发送 FormData(image)
  → 原 ImageValidationController.validate 检查文件部分
  → 原 ImageValidationService.validate / inspect 校验真实内容
  → 返回元数据，页面只接收当前图片对应的结果
```

后端的核心边界保持：Controller 负责 HTTP 输入形状，Service 负责真实图片格式、字节数、像素和解码规则，advice 负责固定错误响应。浏览器入口只改变如何取得 File，不应导致三套后端接口；前端校验改善反馈速度，Java 仍做最终校验。具体后端方法和资源释放见 [5.3a 说明](screenshot-upload.md)。

## 设计与边界

- 拖拽悬停阶段只检查文件类型标识，不尝试读取受保护的文件内容；放下时才取文件。支持 files 和 item.getAsFile 回退；能够识别为文件夹时明确拒绝，不遍历目录。
- 多文件/多张剪贴板图片拒绝，不悄悄选择第一张。空文件、超过 5 MiB、无法取得文件时明确提示。PNG/JPEG 实际内容、尺寸及可解码性仍由 Java 确认，不转换或压缩原图。
- 只有截图区域及其子控件中的主动 paste 才处理图片；区域可点击聚焦，也可用 Tab 聚焦。文字/HTML 粘贴不拦截、不读取，其他表单输入不接收截图粘贴逻辑；没有后台读取剪贴板的权限请求或 navigator.clipboard 调用。
- 链接不转换成图片、不联网抓取。拖到截图区域外的文件只阻止浏览器直接打开文件并提示正确位置，不自动导入；普通文字拖入表单仍由浏览器处理。
- 新图片或无效新图片输入均清除旧预览/旧检查结果，手动字段保持。取消选择器或粘贴纯文字则保留原图片。旧检查通过 revision 失效；这不表示服务器上的旧检查请求已取消。
- 只在用户点击“检查图片”后上传，继续沿用有限 60 秒超时，不自动重发。检查期间仍能换图/移除；手动保存期间禁用截图操作。组件离开页面清理 Blob URL 与窗口事件监听。
- 仍无识别、自动填表、额度、长期存图或自动岗位保存。手机相机/HEIC/方向及四平台专项结果留给 5.3c 和真实设备验收。

## 本机网页验收步骤

1. 刷新前端，进入“添加岗位”。本轮只改前端，无需重启后端或执行 SQL。
2. 从 Finder/资源管理器拖一张 PNG/JPEG 到截图区域，确认区域高亮、放下后预览，点击检查显示格式和宽高；放到区域外应留在原页面并提示正确位置。
3. 用系统截图工具将截图复制到剪贴板，点击截图区域空白处，Windows 按 Ctrl+V、macOS 按 Command+V；预览后点击检查。复制文件名/图片链接未必产生图片数据，可退回选择文件。
4. 同时拖两张、拖文件夹或超过 5 MiB 的文件，确认提示，不静默只选第一张；重新导入合法图能恢复。
5. 检查中粘贴新图，旧结果不恢复；移除、重复选择同一文件、取消选择器均符合页面提示。在公司名输入框粘贴文字正常，截图区域粘贴纯文字不清空原图。
6. 确认手动字段仍保留，图片检查不创建岗位；需要保存测试岗位时使用虚构信息并主动点击保存。确认本项验收后再推进 5.3c。
