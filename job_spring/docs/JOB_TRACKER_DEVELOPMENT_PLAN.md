## 1. 项目目标

开发一个可通过手机和电脑浏览器访问的响应式 Web 应用。用户可以记录岗位、管理投递进度、整理每轮面试的问题；之后可以上传招聘截图，由视觉模型识别内容并填入可编辑表单。

项目的核心流程：

> 找到岗位 → 记录岗位 → 更新投递状态 → 记录面试 → 复盘

### 第一版范围

- 用户注册、登录和退出。
- 手动新增、编辑、查看和删除岗位。
- 按投递状态筛选岗位，并支持关键词搜索和分页。
- 为岗位记录面试轮次、问题、回答要点和复盘。
- 上传招聘截图，识别岗位信息并填入可编辑草稿。
- 手机和电脑浏览器均可正常使用。
- 多个用户的数据彼此隔离。

## 2. 建议技术栈

- **前端：**Vue 3、Vite、JavaScript、CSS；使用 Vue Router 管理页面。第一版先不加入复杂的状态管理库，也可以先不引入 UI 组件库。
- **后端：**Java、Spring Boot、Spring MVC、Spring Security、MyBatis-Plus、Maven。
- **数据库：**MySQL。
- **视觉识别限额：**在实现视觉识别时加入 Redis，用于记录 IP 每日调用次数。
- **部署：**Linux 服务器和 Nginx。Nginx 提供前端页面，并将 `/api` 请求转发给 Spring Boot。

开工时先检查本机 JDK，再按 Spring Boot 官方兼容要求确定并固定版本，不追随未验证的最新版本。[Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)｜[MyBatis-Plus Quick Start](https://baomidou.com/en/getting-started/)

## 3. 页面与响应式设计

手机和电脑使用同一套页面，根据屏幕宽度调整布局。电脑上可以用侧边导航和岗位表格；手机上将表格改为岗位卡片、表单改为单列，并确保按钮和输入区域方便触控。可以使用 CSS 媒体查询适配不同视口。[MDN：媒体查询与响应式布局](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Media_queries)

第一版页面：

1. 登录 / 注册页。
2. 概览页：各状态岗位数量、最近面试记录。
3. 岗位列表页：搜索、状态筛选、新增岗位。
4. 岗位详情页：岗位信息、状态变更、面试轮次。
5. 岗位编辑页：手动录入，或用图片识别后预填表单。
6. 面试记录编辑区：添加轮次、问题、答案要点和复盘。

## 4. 核心数据设计

### `users`

保存用户账号、密码哈希和创建时间。密码只保存哈希，不保存明文。

### `job_applications`

建议字段：所属用户、公司、岗位名称、城市、来源平台、原始链接、薪资、岗位职责、任职要求、学历要求、截止日期、投递状态、创建时间和更新时间。

初始状态可包括：

- 待投递
- 已投递
- 笔试中
- 面试中
- 已获 Offer
- 未通过
- 已放弃

### `interview_rounds`

关联岗位，记录轮次、面试时间、轮次类型、结果和整体复盘。

### `interview_questions`

关联面试轮次，记录问题、自己的回答要点、知识主题和复盘备注。

岗位、面试轮次和问题都要关联所属用户。后端读取或修改记录时必须确认当前用户有权访问，不能只凭前端传入的记录 ID 判断权限。

## 5. 图片识别流程

视觉识别生成岗位草稿，不直接创建岗位：

1. 用户上传截图并预览。
2. 后端检查文件格式、大小和调用额度。
3. 后端调用视觉模型，要求返回固定字段的 JSON。
4. 前端把识别结果填入可编辑表单。
5. 无法识别的字段留空；用户检查、修改后再保存。

初始识别字段：公司、岗位名称、城市、薪资、岗位职责、任职要求、学历要求、来源平台、原始链接和截止日期。模型应将无法确定的内容留空，不自行猜测。

截图默认只用于识别，不长期保存。视觉模型 API Key 只放在服务器配置中。免费额度可能变化，因此手动新增岗位必须始终可用；同时设置全站每日调用上限。

### IP 调用限额

- 当前默认每个IP每天30次、全站每天300次，均为可调整配置项。
- 只在请求即将发送给视觉模型时计数；格式或大小校验失败不扣次数。
- 使用 Redis 计数器和过期时间实现每日额度；Redis 文档介绍了 `INCR` 限流模式。[Redis：INCR 限流模式](https://redis.io/docs/latest/commands/incr/)
- 设置全站每日上限，降低视觉模型免费额度耗尽后的意外费用。
- Nginx 部署时，只信任配置好的代理传来的转发 IP 信息。
- 尽量不长期保存原始 IP；额度记录可以使用服务端密钥生成的 IP 哈希。
- 如果 Redis 不可用，暂时关闭图片识别并提示重试；手动录入仍可用。
- 公共网络下多人可能共用一个出口 IP。加入账号后，可以视使用情况增加账号级限额。

## 6. API 草案

接口字段可以在页面和数据库设计确定后细化，第一版保持接口少而清晰：

```text
POST   /api/auth/register
POST   /api/auth/login
POST   /api/auth/logout
GET    /api/auth/me

GET    /api/jobs
POST   /api/jobs
GET    /api/jobs/{id}
PUT    /api/jobs/{id}
PATCH  /api/jobs/{id}/status
DELETE /api/jobs/{id}

GET    /api/jobs/{id}/interview-rounds
POST   /api/jobs/{id}/interview-rounds
PUT    /api/interview-rounds/{id}
DELETE /api/interview-rounds/{id}

POST   /api/interview-rounds/{id}/questions
PUT    /api/interview-questions/{id}
DELETE /api/interview-questions/{id}

POST   /api/vision/images/validate
POST   /api/vision/extract
GET    /api/vision/quota
```

岗位列表接口支持分页、状态筛选和关键词搜索。所有需要用户身份的接口都由后端验证登录状态和数据归属。

由于这是浏览器应用，可以优先用 Spring Security 管理登录状态和 Cookie，不手写密码加密或令牌算法。开发时通过 Vite 代理 `/api`；部署时让 Nginx 在同一域名下提供页面并转发 API，以减少跨域配置。

## 8. 与 Codex 协作的方式

一次只让 Codex 实现一个阶段中的一个小功能。例如，先做“创建岗位接口和页面”，确认理解后再做“岗位编辑”。每次请它说明改了哪些文件、数据如何流动、你应该理解哪些代码，以及如何手动验证。

用户于 2026-10-20 明确要求：每次完成后，在同一条交付回复中主动讲清本次需要理解的部分，
包括关键代码、执行顺序、这样设计的原因与必要的边界，不等用户另问。
用户主要学习 Java 后端，前端只解释必要的数据流；列出手动检查步骤，区分自动验证与用户验收。
用户验收后，先解答学习问题，再提出下一个小任务的目标、涉及文件、数据流和理由，确认后实施。
用户于 2026-10-21 调整协作方式：一个小任务的后端接口与 UI 操作可以一起实现，方便直接页面验收，无需再新增 HTTP 文件。
开始前仍说明目标、文件、数据流与理由；收到继续指令后推进一个小任务。交付时主动指出关键后端文件、重要方法与设计思想，不能省略学习说明。
