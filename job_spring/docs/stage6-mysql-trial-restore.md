## 本次执行链路与参数

Mac `mysqldump` → 仓库外私有 SQL 文件 → FinalShell SFTP 上传 → Linux 私有目录 → 新建独立临时库 → SQL 导入 → 只读校验。

- 使用已核对的 `mysqldump 9.3.0-commercial`，与源服务器版本一致。
- `--single-transaction --quick`：对 InnoDB 导出一致性快照并逐行读取；导出期间应避免 DDL。试备份不替代正式切换前暂停写入和最终备份。
- `--no-tablespaces --set-gtid-purged=OFF`：不携带源表空间定义或修改目标 GTID 状态的指令。
- `--column-statistics=0 --hex-blob`：不导出直方图统计，二进制值使用十六进制表示。
- `--routines --events --triggers`：请求保留额外对象；本次备份结构摘要未发现这些对象或视图定义。
- 不使用 `--databases`，避免固定建库及 `USE` 指令；使用 `--skip-add-drop-table --skip-add-locks`，不携带删表和插入锁表指令。
- 备份以私有 `.partial` 文件生成，导出成功且非空后改名。备份大小为 17,267 字节，用户已确认 Linux 与 Mac 的 SHA-256 一致；不在文档保存备份摘要或私人路径。
- Linux 私有目录权限 700、SQL 文件权限 600；密码仅通过 `-p` 在本机提示中输入，不附在命令或文档中。
- 临时库为 `job_tracker_trial_20261101`，按 utf8mb4 / utf8mb4_unicode_ci 新建。建库不使用 `IF NOT EXISTS`，通过成功条件连接导入操作，同名库存在时停止，不覆盖已有库。
