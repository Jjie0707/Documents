# 全站视觉更新：角色目录风格

日期：2026-11-02。状态：前端实现、开发验证、独立审阅修正复核和设计文档完成；等待用户页面验收，尚未部署。

## 本次目标与范围

用户先确认“替换整套视觉风格，先给我看设计方向再实现”，随后在 Impeccable 选择页选择“角色目录”。据此采用奶白背景、浅紫导航、粉色主按钮与柔彩岗位卡片，配深靛蓝正文。参考的是角色目录的色彩、圆润感与角色签名，实际页面仍服务于岗位管理任务。

覆盖登录、注册、岗位列表、新增、编辑、详情、面试回顾、找不到页面，以及截图、额度、识别草稿和轮次面板。不增加业务能力；沿用现有接口、字段、校验、权限、分页、显式保存、冲突处理和结果不确定时的保护。正常内容区域让岗位和操作优先，角色仅用于品牌、登录与空状态。

本次只改前端及说明文档。Java、Maven、数据源、私有模型配置和后端接口没有因本轮视觉更新而修改。工作区原有阶段六改动保留，未创建或切换分支，未提交、推送、操作数据库或线上入口。

## 关键文件与执行顺序

页面加载顺序为：

```text
index.html → src/main.js → App.vue → router.js → 对应 views 页面
                                  ↓
                    现有 api.js / auth.js → /api → Java 后端
```

`src/main.js` 先创建 Vue 应用、安装路由并加载全局样式，然后挂载到页面。`App.vue` 提供共同的品牌导航、账号区、主内容和连接状态页脚；`RouterView` 显示当前页面。本轮新增“跳到主要内容”入口，并保证页面只有一个主内容区域。

`frontend/src/style.css` 定义颜色、字体、按钮、输入框、状态提示、表单和焦点等共用规则；它导入 `styles/layout.css`，后者负责页面宽度、卡片网格和响应式结构。CSS 变量使全站共用一套参数，避免每个页面单独指定近似颜色和圆角。

关键参数：正文 `--ink: #2e3457`，背景 `--ground: #fbf8f2`，主按钮 `--primary: #b23c70`，导航 `--lavender: #eee5f8`；输入框圆角 10px、面板圆角 16px。浅色用于背景，深色用于文字与操作，避免柔彩导致内容难读。按钮通常至少 44px 高，输入字号 16px（每页条数是较紧凑的辅助选择器），键盘焦点有明确轮廓；动效约 180ms，并尊重减少动态效果设置。页面与文本框滚动条使用奶白轨道和浅紫灰滑块。

标题与品牌使用自托管 `LXGW Marker Gothic / 霞鹜漫黑`，正文、岗位卡片中的数据标题和表单保留系统字体。`@font-face` 指向 `frontend/public/fonts/lxgw-marker-gothic.woff`；`font-display: swap` 让字体下载前先显示回退字形，避免等待时没有文字。全字库保留 15,285 个 Unicode 映射，约 1.85MB，会增加首次访问下载量；后续部署应设置静态资源缓存。本轮未改 Nginx 缓存配置或安装系统字体。来源、原文件摘要和转换方式见 [SOURCE.md](../frontend/public/fonts/SOURCE.md)，OFL 许可随构建分发。

`views/JobsView.vue` 把“添加岗位”放到页面标题旁，保留搜索、状态筛选和分页。桌面岗位卡片为双列，700px 及以下单列。卡片底色循环呈现四种柔彩，**不代表业务状态**；状态由右上方文字与圆点共同表达。

`JobDetailView.vue` 在 960px 以上显示岗位信息与操作区两栏，较窄时依次堆叠；三个栏目保留原有切换与操作互斥逻辑，将装饰编号换为图标。新增、编辑和回顾页沿用原表单与提交方法，只调整容器、间距与层级。

共用小组件：

- `AppIcon.vue`：统一的 SVG 图标；图标由旁边文字解释，装饰图形不重复朗读。
- `RecordCompanion.vue`：文件夹角色图片，空替代文本用于装饰，功能名称仍由文本提供。
- `LoadingState.vue`：统一加载骨架及可朗读的加载提示。
- `ScreenshotUploadPanel.vue`：选图区域与展开说明；隐私、上传与模型识别的区别仍直接可见。
- `VisionQuotaPanel.vue`、`RecognitionDraftPanel.vue`：重新组织额度、刷新和十字段草稿展示，原来的识别、确认填入与保存职责不变。

操作请求仍由原方法经原 API 发出。例如新增岗位依次为：选择截图（可选）→ 检查图片 → 识别草稿 → 人工确认填入 → 编辑字段 → 明确点击保存 → 原 `POST /api/jobs`。识别不会直接保存；已填写内容的冲突选择、保存结果未知时的禁止重发均保留。
