## 接口与边界

沿用 GET /api/interview-rounds/{id}/questions，增加可选 keyword；page、questionId 和响应结构不变。

- keyword 首尾 strip，缺省或空白表示不搜索；最多 100 个 Unicode 码点，超长为脱敏 400 / fields.keyword。
- 在当前用户当前轮次的问题 question、回答要点 answerNotes、知识主题 knowledgeTopic、复盘 reviewNotes 中做不区分大小写的包含查询，任一字段命中即可。
- `%`、`_`、`!` 均按字面查询，不允许借关键词指定通配符；引号、反斜杠仍是普通输入。
- 固定每页 10 条、ID 倒序。total、totalPages、分页行和 questionId 定位都使用相同搜索范围。无匹配时 items=[]、page=1、total=0、totalPages=0；超末页自动修正。
- questionId 只有在当前用户、当前轮次且符合 keyword 时才定位；被排除、其他轮次、越权或不存在目标都回退普通页，不泄露其他范围。
- 仍需登录，成功 no-store；不存在或越权轮次仍统一 ROUND_NOT_FOUND / 404。搜索仅只读，写接口、事务、CSRF、外键和表结构不变。
- 搜索范围限当前轮次，不是跨岗位题库。主题字段包含查询不等于下一项的知识主题筛选。

示例：GET /api/interview-rounds/{id}/questions?page=1&keyword=Spring。客户端使用 URLSearchParams 编码关键词。

## Java 执行顺序与设计

1. InterviewQuestionReadController.list 使用 @Valid @ModelAttribute 接收 InterviewQuestionPageQuery，从 @AuthenticationPrincipal 取 userId；客户端不决定归属。
2. InterviewQuestionPageQuery 构造器规范化关键词，@CodePointLength 校验长度；toString 不输出关键词。
3. InterviewQuestionReadService.listForUser 先核对本人轮次，再调用 conditions 统一构建条件。SQL 逻辑为 `round_id = ? AND user_id = ? AND (字段1匹配 OR 字段2匹配 OR 字段3匹配 OR 字段4匹配)`。括号防止 OR 绕过归属限制。
4. conditions 先把 `!` 转为 `!!`，再将 `%`、`_` 转为 `!%`、`!_`；最后才在两侧加 `%`，用固定片段 `LOWER(column) LIKE LOWER({0}) ESCAPE '!'`。{0} 由 MyBatis-Plus 绑定值，关键词不拼进 SQL。
5. 总数查询、目标是否匹配、目标之前条数、取页数据都重用 conditions。目标页为“符合条件且 ID 更大的条数 / 10 + 1”，不会拿未筛选的位置定位。
6. InterviewQuestionMapper.selectPageRows 接收 Service 构造的 Wrapper，再做 ORDER BY / LIMIT / OFFSET。`${ew.customSqlSegment}` 只接收程序构造的条件结构（沿用岗位分页做法），用户内容仍通过参数绑定，不能传任意 SQL。旧的无筛选前置计数改为带相同条件的 selectCount。
7. Response 保持 items/page/size/total/totalPages，Controller 返回 no-store。

职责保持 Controller 处理 HTTP/身份、common 表达参数、Service 组织规则、Mapper 访问数据库；没有新依赖或任意重构。

## 页面数据流

InterviewQuestionsPanel 增加搜索输入、“搜索问题”“清空搜索”，回车可提交。输入草稿 keyword、最近提交 submittedKeyword、已成功展示 appliedKeyword 分开保存：输入不立即过滤；翻页和失败重试使用已提交条件，结果说明只显示已成功生效条件。新搜索与清空回第 1 页；刷新/重新进入回顾页恢复默认，不存浏览器持久化数据。

- requestNumber 只允许最新请求更新页面；读取期间允许提交不同关键词，旧响应和旧 finally 不覆盖新结果/加载状态。
- 保留每条右侧上下编辑/删除、折叠回答/复盘与原分页；筛选序号代表匹配结果位置，目标以 ID 为准。
- 新增、编辑、删除成功后按原提交条件重新读取；保存内容不再匹配时明确提示“已保存/已更新，当前搜索结果未包含该问题，可清空搜索查看”。编辑后匹配总数减少则自动修正末页。
- 无匹配提示调整或清空搜索，仍允许新增；不把“无匹配”说成没有任何记录。未搜索且本轮无记录时沿用“无面试过程记录”和添加记录。
- 草稿、写入、删除确认或结果不确定期间禁用搜索/清空；加载失败不显示为搜索空态，也不允许基于失败结果新增。
- 写入响应无法确认时仅 GET 核对，不自动重发写入。保存/删除核对均清空关键词，并按目标 ID 定位无筛选列表，避免把“被筛掉”误当“不存在”。核对失败继续保护，编辑由用户核对后恢复；删除仍存在需重新确认。
- 桌面输入与按钮一行；700px 及以下输入单独一行、两个按钮并排，问题右侧按钮保留。

## 网页手动验收

1. 重启后端并刷新前端。打开岗位详情 → 对应轮次右侧“面试回顾”。准备少量专用虚构问题，分别在问题、回答、知识主题、复盘中放不同关键词。
2. 搜索其中关键词，检查仅当前轮次命中、总数及结果条件；回车、清空、首尾空白均可用。测试 `%`、`_` 时只匹配含该字符的问题。
3. 可选准备 11 条匹配，下一页仍保留条件；在输入框改词但不提交，翻页仍用原条件。重新搜索回首页；无匹配有明确提示，清空后恢复本轮记录。
4. 在专用问题上编辑，使四字段都不再包含关键词：应提示更新成功及当前搜索未包含，清空可查看；新增不匹配的问题同样保存成功。删除专用问题后重新计算匹配数，其他问题不受影响。
5. 检查编辑/删除确认期间搜索按钮锁定；手机检查输入/按钮分行和问题右侧编辑/删除排列。网络异常核对只读取，不重复保存/删除。
