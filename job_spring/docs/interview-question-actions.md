# 阶段 4 · 单个面试问题编辑与删除

2026-10-23，用户确认新增/查看问题及独立回顾页验收通过，要求先补每个具体问题右侧上下排列的编辑、删除按钮，再完成[详情右侧栏目切换](job-detail-tabs.md)。本次两项均开发完成，等待用户验收；没有推进搜索或主题筛选。

## 当前接口与范围

- PUT /api/interview-questions/{id}：完整更新当前问题的 question、answerNotes、knowledgeTopic、reviewNotes，200 返回规范化后的内容对象。
- DELETE 同路径：只删除本人指定问题，204 空响应；回答、主题、复盘随该行删除，岗位、轮次、其他问题保留。物理删除没有恢复入口。
- 两个接口需要登录与有效 CSRF，成功 no-store；只信路径 ID 与当前身份，不接受修改主键、userId 或 interviewRoundId。
- PUT 问题必填（最多 2000 码点）；选填回答 4000、主题 100、复盘 2000。首尾 strip，选填缺省/null/空白统一清空为 NULL；重复保存相同内容仍成功。
- 不存在、已删除或越权统一 404 / QUESTION_NOT_FOUND。非法路径/JSON/字段为 400；约束冲突 409、数据库访问失败 503，错误不回显内容或底层细节。

GET /api/interview-rounds/{id}/questions 新增可选 questionId（正 Long）：在当前用户当前轮次范围内按 ID 定位实际问题页。按 ID 倒序，目标之前的条数 / 10 + 1 即其页码；目标不在该范围则回退普通页，不泄露其他用户或轮次记录。仍固定每页 10 条，超末页修正。

## Java 文件与执行顺序

Security → InterviewQuestionUpdateController / DeleteController → InterviewQuestionWriteService 的 updateForUser / deleteForUser → Mapper → 返回 200 / 204。

两个 Service 入口分别有 @Transactional，共用新业务内部的私有 lockOwnedQuestion，不重构已有 CRUD：

1. 用问题 ID + userId 初步查问题，只为定位所属轮次与岗位。
2. 核对本人父轮次，锁定本人岗位（lockOwnedJob）。
3. 按相同顺序当前读轮次、当前读问题（FOR UPDATE），重新确认归属与父子关系。
4. 才允许 UPDATE / DELETE，SQL 本身也限定问题 ID、userId、所属轮次。

锁保持到事务结束，与已有新增问题、轮次编辑/删除、岗位关联删除使用同一父锁顺序；等待期间记录消失后返回 404，不拿旧快照继续写入。任一步异常事务回滚，生产 RESTRICT 外键保持。

更新用 LambdaUpdateWrapper 显式 set 四字段，包含 NULL；避免实体更新策略跳过 null 而无法清空。已在锁内确认存在，不用 UPDATE 影响行数判断未找到，兼容 MySQL 同值更新返回 0；完成后当前读结果返回。删除则用 DELETE 影响行数确认删到目标。

UpdateInterviewQuestionRequest 独立表达 PUT 完整目标值，沿用新增字段规则及 toString 内容脱敏。InterviewQuestionMapper 增加当前读与分页前置计数；Advice 增加两个 Controller 和 QUESTION_NOT_FOUND，不改变原轮次不存在时的 ROUND_NOT_FOUND。

## 页面约定与数据流

每条问题左侧显示内容/主题/折叠回答与复盘，右侧“编辑”在上、“删除”在下，手机保持右侧排列。按钮名称带问题序号用于读屏，目标以记录 ID 为准。

编辑预填四字段；取消不发 PUT、恢复原按钮焦点；保存后 GET 按 questionId 定位，不跳回首页。字段错误保留草稿，其他问题操作与问题翻页在编辑草稿期间禁用。选填留空的清除含义在表单明确展示。

删除按钮先展开目标与不可恢复范围，默认焦点取消，取消/Escape 不发 DELETE；确认/提交/不确定时其他写入和返回入口互斥，函数入口防连点。成功后 GET 当前页，末页自动修正，最后一条删除后显示“无面试过程记录”和添加记录。204 后列表读取失败保留删除成功提示，重试只 GET。

编辑响应丢失时保留草稿，只读加载并按 ID 定位后由用户确认恢复，不自动重发 PUT。删除响应丢失时保留目标，只读核对：仍存在则重新确认；已不存在则更新列表，不声称必由本次请求删除；读取失败继续锁定。问题写入 404 只重取问题列表，不误把整个轮次当作不存在。
