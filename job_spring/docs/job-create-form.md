## 必要的数据流

```text
主页点击“添加岗位”
  → 路由守卫通过 /api/auth/me 检查登录
  → /jobs/new 表单，输入绑定到内存中的 form
  → 点击保存，先做必填和 Unicode 字符数检查
  → post('/api/jobs', { ...form })
      → GET /api/auth/csrf 获取当前有效 Token
      → POST /api/jobs 提交四字段 JSON + Token，浏览器携带 Cookie
      → 后端继续执行最终校验，确定归属和初始状态
  → 返回新 ID
  → router.replace 跳转详情
  → 详情通过 GET /api/jobs/{id} 读取服务器保存的结果
```

`v-model` 将输入内容同步到 `form`，不保存到 localStorage。
`fields` 的键名与 Java 校验响应一致，例如 `companyName`，用于将后端提示放到对应输入框下方。
前端先检查常见空白与长度，后端仍是最终校验依据；文本规范化和空白选填项转 NULL 继续由后端完成。
没有使用 HTML maxlength 截断输入，避免将 UTF-16 单元数当成 Unicode 字符数。

`busy` 在开始请求前设为 true：函数首先检查它，fieldset 和页面返回按钮同时禁用。
保存期间显示“正在保存…”，防止连续点击造成多次提交。
后端字段错误会保留内容、显示提示，并在解除禁用后聚焦对应字段。
收到 401 时清除前端账号状态并跳转登录页；会话失效后的表单不跨登录保存。
其他错误保留输入。连接失败或超时时，提示先回列表确认保存结果，不自动重发新增请求。
取消/返回直接离开，不保存草稿；离开页面后，尚未完成的请求不会将用户重新带回详情。
