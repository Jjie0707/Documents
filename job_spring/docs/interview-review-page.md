## 当前页面约定

- 岗位详情只展示当前轮次信息，右侧“面试回顾”入口与轮次标题顶部对齐；窄屏也保留在右侧。
- 岗位详情不再挂载问题组件或查询问题列表，避免长列表撑开详情；轮次编辑、删除、上一轮/下一轮和新增轮次保持。
- 有轮次即有对应回顾入口；没有轮次时没有回顾入口，保持“暂无面试轮次，可以先添加第一轮”和新增按钮。
- 点击进入 `/jobs/{id}/interview-rounds/{roundId}/review`，显示公司、岗位及第几轮，避免混淆上下文。
- 回顾页无问题时不显示空的“本轮问题（0）”列表，显示“无面试过程记录”和“添加记录”。
- 有问题时沿用问题内容、知识主题及折叠的“查看回答与复盘”，每页 10 条、最新在前，仍可新增问题。
- “返回岗位详情”带 `?roundId=目标ID`，详情重新按记录实际位置定位；第 2 轮返回后仍为第 2 轮，不把 roundNo 当页码。
- 没有定位参数时详情仍默认第 1 页；问题页刷新仍从问题首页读取，不把问题分页和轮次分页混用。

## 涉及文件与数据流

router.js 新增登录保护路由；InterviewRoundsPanel.vue 移除内嵌问题组件，改为轮次右侧 RouterLink；JobDetailView.vue 读取并校验定位 query，传给轮次组件。

InterviewReviewView.vue 的 loadReview 并行读取已有岗位详情和带 roundId 的轮次分页，精确匹配返回记录 ID 后，才挂载 InterviewQuestionsPanel。分页接口在目标轮次找不到时会回退到普通页，因此不能直接拿 items[0] 当目标；错配时显示无法查看，不发问题请求，也不提供添加入口。

页面绑定的轮次/岗位参数变化时重新加载，用请求编号和卸载标记防旧响应覆盖新上下文。问题接口报告轮次不存在时隐藏旧内容；读取失败显示错误，不当作“无面试过程记录”。

InterviewQuestionsPanel.vue 复用已有 GET/POST、四字段校验、分页、防连点、草稿与响应不确定核对。busy 现传给回顾页，加载/草稿/保存/不确定期间页面的“返回岗位详情”入口禁用，取消或核对后恢复；详情页的编辑/删除确认期间也禁用“面试回顾”入口。

## 后端学习边界

本次没有修改 Java 接口、Service、Mapper、Security 或数据库，沿用：

- GET /api/jobs/{id}：JobReadService 按当前用户获取岗位。
- GET /api/jobs/{id}/interview-rounds?roundId=...：InterviewRoundReadService.listForUser 先确认岗位归属，再定位所属轮次的实际页。
- GET /api/interview-rounds/{id}/questions：InterviewQuestionReadService.listForUser 确认轮次归属，再限定轮次/用户查询分页。
- POST 同问题路径：InterviewQuestionCreateService.createForUser 继续按“本人轮次 → 父岗位锁 → 当前读轮次 → INSERT”的事务顺序保存。

前端匹配用于避免显示错误页面上下文，权限仍由后端和各 SQL 归属条件执行，不依赖前端校验。无新依赖、改表或 HTTP 文件。
