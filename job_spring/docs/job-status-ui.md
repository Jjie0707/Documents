## 必要的数据流与理解要点

```text
GET 详情，得到 job.status
  → 页面显示当前状态，并将其作为 selectedStatus 的初始值
  → 用户选择新值：只改变 selectedStatus，不更新 job.status
  → 点击保存：记录当前岗位 ID、选择值和请求编号，设置 savingStatus
  → patch('/api/jobs/{id}/status', { status })
      → sendWithCsrf 获取当前有效 CSRF Token
      → PATCH 发送状态 JSON，浏览器携带会话 Cookie
  → 后端成功返回岗位：更新 job 和 selectedStatus，显示成功提示
  → 刷新详情或返回列表：通过 GET 从服务器读取已保存状态
```

1. **待提交值和确认值分开。** selectedStatus 是下拉框选择；job.status 是最近从服务器确认的值。
   后端没有成功返回时，不把选中值显示为当前已保存状态。
2. **POST 与 PATCH 共用 CSRF 提交封装。** sendWithCsrf 在提交前获取当前有效 Token，
   再按方法发送请求。post 仍支持登录所需的表单编码、注册/新增 JSON 和无请求体的退出；
   patch 发送状态 JSON。本次获取 Token 的调用策略不表示每次请求都会生成或消耗新 Token。
3. **提交中禁用仅保护页面交互。** savingStatus 同时用于函数入口判断和禁用控件，防止连续操作重复发送。
   没有状态变化时前端不提交，但后端仍支持重复设置相同状态。
4. **连接失败不等于后端没保存。** ApiError.status 为 0 时，页面保留最近确认的状态，
   将结果标为不确定，暂时禁用提交，提供“重新加载岗位”通过 GET 核对。不会自动重发 PATCH。
5. **异步结果只用于原页面。** 开始保存时固定岗位 ID 和请求编号；返回后检查组件是否还在、编号是否仍匹配。
   切换岗位或离开详情后，旧响应不覆盖新页面，也不会跳回旧页面。
   离开页面不会撤销已经发送到服务器的更新；原岗位仍可能保存成功。

## 错误与会话处理

| 情况 | 页面行为 |
| --- | --- |
| 400 | 优先显示 fields.status，否则显示通用错误，保留确认值与待提交选择 |
| 403 / 503 | 显示服务端提示，不显示成功，保留确认值与选择，允许再次操作 |
| 401 | 清除前端账号状态并回登录页 |
| 404 | 隐藏旧岗位内容，显示“岗位不存在或无法访问”，可重新加载 |
| 连接失败 / 超时 | 提示保存结果未确认，先重新加载岗位核对 |

未新增状态字段、浏览器持久化、自动重试或后端权限规则。
归属隔离和状态合法性仍由已验收的后端接口执行。
