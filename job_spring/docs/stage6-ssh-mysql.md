## 请求链路和职责

```text
Mac MySQL 客户端
  → TCP 127.0.0.1:13306（Mac SSH 进程监听）
  → SSH 加密连接
  → TCP 127.0.0.1:3306（Linux 本机 MySQL）
  → 临时库 job_tracker_trial_20261101
```

SSH 负责传输和认证 Linux 登录身份，MySQL 仍单独校验数据库账号密码。SSH 密码与数据库密码用途不同；本次用户使用密码登录 SSH，没有要求提供私钥或将密码发送到聊天。

绑定 Mac 回环地址使转发端口仅供本机访问。数据库无需为这条链路开放公网 3306，也不需要更改现有 MySQL 监听地址。公网 SSH 入口使用用户已有连接，本轮未调整安全组、服务器 SSH 配置或防火墙。

## 转发参数

本轮使用的命令结构如下，服务器地址、账号和端口仅由用户在本机提供，不保存实际值：

```sh
ssh -N -T \
  -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -o StrictHostKeyChecking=ask \
  -L 127.0.0.1:13306:127.0.0.1:3306 \
  -p SSH_PORT \
  SSH_USER@SSH_HOST
```

- `-L` 的第一个地址/端口是 Mac 监听点，第二个地址/端口由 Linux 侧访问；两处 127.0.0.1 所指机器不同。
- `-N -T` 不执行远程命令、不分配终端；认证后没有输出、窗口持续占用是正常运行状态。
- `ExitOnForwardFailure=yes` 在转发监听创建失败时退出，不代表目标 MySQL 已验证可达，必须另做数据库连接验证。
- `ServerAliveInterval=30` 和 `ServerAliveCountMax=3` 用于检测连接失效，不提供自动重连。
- `StrictHostKeyChecking=ask` 保留首次服务器身份核对；可通过已有可信 FinalShell 连接查询服务器公钥指纹后比较。本记录不声称用户逐项提供过指纹核对结果。

当前是前台手动隧道，需要保持终端开启；不是开机启动、自动恢复或全天在线方案。后续常驻运行须另行准备维护方式，不能把本次连接成功当作持久运行验收。

- 关闭本次转发：在运行该 ssh 命令的专用终端按 Ctrl+C，只停止自己的前台 SSH 连接，不终止其他 SSH/FinalShell 会话。
- 关闭后可检查本机 13306 不再监听；本次未实际断开回退，避免中断用户正在保留的转发。
- Mac 项目未切换数据源，隧道关闭不会影响其原数据库连接；以后项目若使用此转发，关闭会使该远程数据源不可达，需要单独安排切换和中断窗口。
