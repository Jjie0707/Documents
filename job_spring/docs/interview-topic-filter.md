## 接口和规则

沿用 GET /api/interview-rounds/{id}/questions，增加可选 topic；keyword、page、questionId 规则保留。分页响应新增 topics，其他字段保持：

```text
items / page / size / total / totalPages / topics
```

- topic 表示知识主题的完整名称，不做包含匹配；不区分大小写，首尾 strip，缺省/空白表示全部主题。最多 100 个 Unicode 码点，超长返回 400 / fields.topic，不回显输入。
- topic 与 keyword 取交集，逻辑为：本人 + 当前轮次 + 完整主题相等 +（四字段关键词任一命中）。关键词仍按字面包含查询，主题中的 %、_、!、引号等均是普通字符。
- “全部主题”只取消主题限制，保留已提交关键词；“重置条件”清除两项并回第 1 页。未填写主题的记录包含在全部主题中，本次不增加“仅未填写”选项。
- 主题可选项来自本人当前轮次的全部记录，不受关键词、选中主题、页码影响。不展示其他轮次/岗位/用户主题，不从本页十条记录推导选项。
- topics 排除 NULL/空白名称，按 LOWER(knowledge_topic) 分组、排序；同名大小写只显示一项，用 MIN(knowledge_topic) 选一个已有写法用于展示。不创建主题表，不合并或改写原记录。
- 允许查询当前不存在的合法主题，返回零匹配及本轮真实选项，不将它视为非法枚举值；已有主题可能在其他页面被改名或删除。
- 每页 10 条、ID 倒序不变。total、totalPages、分页数据和 questionId 定位共用全部筛选条件；目标被条件排除或不在归属内时回退普通页，超末页修正，零结果 page=1/totalPages=0。
- 登录、父轮次统一 404、错误脱敏与成功 no-store 沿用原接口；没有改写入权限、事务、外键、表结构或新增 HTTP 文件。

## Java 学习顺序

1. InterviewQuestionPageQuery 增加 topic，构造器 strip/空白转 null，@CodePointLength 做边界校验，toString 继续脱敏。
2. InterviewQuestionReadController.list 绑定并校验参数，从当前登录身份取 userId，再进入 Service；不信任前端传入归属。
3. InterviewQuestionReadService.listForUser 先确认本人轮次。conditions 统一创建 Wrapper，在归属条件后加入 `LOWER(knowledge_topic) = LOWER({0})`，再 AND 原四字段关键词分组。
4. {0} 是 MyBatis-Plus 参数绑定占位符；固定 SQL 片段与主题值分开，避免用户文本成为 SQL。主题用等号，关键词用带转义的 LIKE，两种需求不混用。
5. listForUser 让计数、目标匹配、目标前置计数和 selectPageRows 共用 conditions，保持筛选和分页一致。
6. InterviewQuestionMapper.selectTopicsForRound 额外执行一次限定 roundId + userId 的分组查询，取整轮主题列表。这里有意不传筛选 Wrapper，避免筛选结果反过来限制下拉选项。
7. InterviewQuestionPageResponse 新增 List<String> topics，和分页数据同一响应返回。页面一次 GET 即可同时刷新结果和可选主题。

职责仍是 common 表达参数/响应、Controller 管 HTTP 和身份、Service 组织规则、Mapper 执行 SQL、Advice 统一错误。没有新依赖或无关重构。

## 页面数据流

InterviewQuestionsPanel 在搜索框旁增加“知识主题筛选”下拉框，默认“全部主题”。选择主题不会立即改变结果，点击“搜索问题”或搜索框回车时与关键词一起提交。原“清空搜索”按钮改为“重置条件”。700px 以下输入、主题各占一行，两个按钮并排，问题右侧编辑/删除保留。

关键词和主题各自区分输入草稿、最近提交、成功展示三个状态。翻页和失败重试使用最近提交的一对条件，输入草稿不偷换请求；最新 requestNumber 才能更新数据、选项和加载状态。生效说明明确展示关键词、主题和匹配总数。

- 新增/编辑/删除成功后按原提交条件刷新，topics 随 GET 更新；不匹配的问题仍提示保存成功及可重置条件查看。
- 最后一条选中主题的记录改名/删除后，继续保留当前选择并显示零匹配，不静默取消条件。下拉框保留当前草稿选项用于显示；重置后消失，不把它当作新增主题写回服务器。
- 草稿/写入/删除确认/结果不确定期间锁定主题与关键词操作；读取期间允许提交另一组条件，旧响应不会覆盖新结果。
- 保存、删除结果不确定时只读核对会同时清空关键词和主题，按问题 ID 定位完整列表，避免将被筛掉的问题误判为已删除；核对失败仍锁定，不能自动重发写入。
- 刷新或重新进入回顾页恢复默认条件，不做浏览器持久化。
