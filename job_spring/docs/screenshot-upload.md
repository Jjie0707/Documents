## 接口与边界

`POST /api/vision/images/validate`，要求登录会话和有效 CSRF Header，使用浏览器生成 boundary 的 multipart/form-data。

- 文件部分必须只有一个，字段名为 `image`。重复 image、其他文件字段或缺少文件都返回 400；额外文本参数不参与业务处理。
- 实际内容只接受 PNG/JPEG，不依赖扩展名、文件名或客户端 MIME。文件名不用于路径、返回值或日志。
- 文件最多 **5 MiB（5,242,880 字节，含边界）**；整个 multipart 请求最多 6 MiB，给字段头和 boundary 留余量。
- 宽、高各为 1～10,000 像素；总像素最多 **12,000,000**，含边界。先读取尺寸并检查，再解码像素；像素乘法使用 long。
- 检查完整结尾标记和实际解码；损坏、截断、读取警告均拒绝。PNG 要求以完整 IEND 结束，JPEG 要求以 EOI 结束；当前不接受结尾后附带额外内容的文件，不承诺支持所有照片扩展形式。
- 成功返回真实格式、媒体类型、字节数和宽高，Cache-Control 为 no-store；没有图片 ID、存储路径、文件名、岗位内容或虚构识别字段。

示例响应（虚构图片）：

```json
{"format":"PNG","mediaType":"image/png","sizeBytes":780,"width":320,"height":240}
```

| HTTP 状态 | 主要含义 |
| --- | --- |
| 200 | 图片检查通过，仅返回元数据 |
| 400 | 文件部分不正确、空文件、损坏/无法完整读取、尺寸或总像素超限、multipart 解析失败 |
| 401 | CSRF 校验通过但没有登录身份 |
| 403 | CSRF 缺失或无效；未登录时也可能先返回该状态 |
| 413 | 单文件或请求大小超限 |
| 415 | 实际格式不是 PNG/JPEG，或请求不是 multipart |

业务错误只返回固定 code/message，不回显文件内容、文件名、解码器消息或底层异常。非 multipart 的 415 沿用 MVC 媒体类型拒绝。

## 关键后端文件与执行顺序

```text
浏览器 File → 本地 Blob URL 预览
  → 用户点击检查 → 获取 CSRF → FormData(image)
  → Security 登录/CSRF
  → Servlet multipart 大小限制与解析
  → ImageValidationController 检查文件部分
  → ImageValidationService.validate 限制实际读取字节数
  → inspect 检测真实格式 → 宽高/总像素 → 完整结尾与解码
  → 释放流、reader、像素缓冲区 → 仅返回元数据
```

1. `vision/common/ImageUploadLimits.java`：集中定义文件、单边和总像素上限。该上限是本阶段的业务限制，不是已核实的模型供应商限制；后续接入时再核对。
2. `vision/controller/ImageValidationController.java`：接收所有文件部分，明确只允许 `image` 一张，委托 Service 并返回 no-store 响应。数据不关联岗位或上传记录，因此没有新增 Mapper、表或图片下载接口；身份由既有 Security 保证。
3. `vision/service/ImageValidationService.java` 的 `validate`：先看声明大小，再用 `readNBytes(MAX_BYTES + 1)` 检查实际字节数，避免无界读取或仅信声明值。输入流通过 try-with-resources 关闭。
4. `inspect`：使用 JDK ImageIO 的真实内容 reader，而不是扩展名；显式 MemoryCacheImageInputStream，避免默认 ImageIO 缓存可能落盘。`getWidth/getHeight` 在完整解码前执行，`(long) width * height` 防止整型溢出。通过尺寸、结尾检查后才 `reader.read(0)`，并处理解码警告、异常及资源释放。
5. `vision/advice/ImageValidationExceptionHandler.java`：处理该 Controller 的固定业务错误；`MultipartUploadExceptionHandler.java` 只对 multipart 大小/解析异常提供全局处理，因为这些异常可能早于 Controller 匹配发生。没有全局捕获普通业务异常或改变已有错误规则。
6. `application.yaml`：multipart 单文件 5MB、请求 6MB、file-size-threshold 6MB，让合法上传留在内存。Tomcat max-swallow-size 为有限 8MB，使略超请求上限时能丢弃剩余请求体并返回 413；不是无限接收。远超丢弃上限的异常请求仍可能直接断开，浏览器正常入口会先拒绝超过 5 MiB 的文件。

未新增依赖，无生产改表、岗位写入或 HTTP 文件；不使用 transferTo、磁盘图片缓存、上传文件名拼路径或长期保存图片。multipart 容器和 ImageIO 的临时资源在请求结束释放；后续真实识别必须复用服务端校验，不能把本次元数据响应当成可跳过校验的凭证。

## 必要前端数据流

`ScreenshotUploadPanel.vue` 独立管理选择、Blob URL、预览和检查状态；`JobCreateView.vue` 只嵌入该组件，手动保存时禁用截图操作。`api.js` 新增 postMultipart，复用 Cookie 和获取 CSRF 的策略，不手写 multipart Content-Type，让浏览器附带正确 boundary。

本地先拒绝空文件和超过 5 MiB 的文件；其余最终规则由后端确认。预览失败提示更换图片，成功预览不代表服务端校验通过。accept 是选择提示，不能当作后端安全规则。

选择器值读取后清空，允许重新选择同一文件；取消选择不移除当前图片。页面用明确的选择/替换按钮和独立文件名展示，避免原生选择器清空后显示“未选择文件”造成混淆。替换、移除、离开页面时撤销旧 Blob URL；revision 与 active 防止旧检查响应覆盖新选择或已离开的页面。检查期间可以替换或移除；重复点击由 checking 拦截。401 沿用清理前端身份和返回登录页，其他错误保留选择并允许重试。
