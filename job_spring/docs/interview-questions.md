## 接口与字段

- `POST /api/interview-rounds/{id}/questions`：路径是轮次记录 ID，成功 201，返回保存后的五字段对象。
- `GET /api/interview-rounds/{id}/questions?page=1`：返回 `{items,page,size,total,totalPages}`，固定每页 10 条，按问题 ID 倒序，最新记录在首页。
- page 默认 1，空参数沿用绑定默认值；小于 1、非整数、超出 Integer 范围均为字段级 400；超过末页自动修正，空列表 page=1、totalPages=0。
- 读写成功响应均 `Cache-Control: no-store`。当前没有问题详情接口，不返回指向未实现详情接口的 Location。

| 请求字段 | 规则 |
| --- | --- |
| question | 必填，最多 2000 个 Unicode 码点 |
| answerNotes | 选填，最多 4000 个 Unicode 码点 |
| knowledgeTopic | 选填，最多 100 个 Unicode 码点，当前为一个自由文本主题 |
| reviewNotes | 选填，最多 2000 个 Unicode 码点 |

四字段先 strip 去除首尾空白；选填字段缺省/null/空白统一 NULL，问题规范化后为空则 400。保留内部换行。TEXT 字段设置应用上限，便于填写和验证；主题沿用数据库 VARCHAR(100)。前端按码点计长，后端 CodePointLength 最终校验。

只接收内容 DTO，主键由数据库生成，用户从 Security 获取，轮次从路径确定。伪造 id/userId/interviewRoundId 参数或 JSON 不会覆盖原记录或改变归属。响应仅含 id/question/answerNotes/knowledgeTopic/reviewNotes，不返回用户、父轮次或内部字段。

问题内容不是轮次编号，本次没有增加问题唯一性规则；独立确认的新增请求各建一条。页面防连点，响应不确定时先核对而非自动重发，避免误操作重复。

## Java 执行与职责

POST → Security 登录/CSRF → InterviewQuestionCreateController.create（路径与身份、@Valid）→ InterviewQuestionCreateService.createForUser（事务与归属）→ Mapper INSERT → 返回 201。

Service 先查本人轮次定位父岗位，调用 JobMapper.lockOwnedJob，随后 selectOwnedRoundForUpdate 重新当前读轮次。只有确认目标仍存在并归属一致才创建实体和插入。锁顺序与轮次新增/编辑/删除、岗位关联删除一致，父锁保持到提交，避免删除与问题插入交错后留下悬空数据。

GET → Security → InterviewQuestionReadController.list → InterviewQuestionReadService.listForUser → 确认本人轮次 → 带轮次 ID 和 userId 的 COUNT + LIMIT/OFFSET 查询 → 映射响应。归属在 SQL 中限定，不能仅靠 UI 隐藏入口。

沿用 interview/common、controller、service、mapper、advice、exception，扩展既有 InterviewQuestionMapper 为 BaseMapper，同时保留两个已验收删除清理方法。没有重构旧业务、修改生产表或增加依赖/HTTP 文件。

InterviewQuestionExceptionHandler 仅覆盖两个问题 Controller：

- 参数/格式错误 400，fields 定位字段，不回显原始内容和类型转换细节。
- 父轮次不存在、已删除或越权统一 404 / ROUND_NOT_FOUND，不泄露其是否有问题。
- 完整性冲突 409、其他数据库异常 503，均返回通用提示。
- 登录/CSRF 仍由 Security 返回 401/403；没有放开保护。

## 页面与数据流

岗位详情 → 当前轮次右侧“面试回顾” → 独立回顾页核对岗位与目标轮次 → InterviewQuestionsPanel 按 roundId GET → 问题列表、数量与分页。轮次仍一页一轮，问题每页 10 条。详情不再直接展示问题；返回时按 roundId 定位原轮次。没有问题显示“无面试过程记录”和“添加记录”，没有轮次则没有回顾入口。详见[回顾页面约定](interview-review-page.md)。

每条问题显示问题与主题，回答/复盘默认折叠，可展开查看，Vue 文本插值不执行 HTML。空态和读取错误分别显示，重试保留提交的问题页码。

新增问题 → 四字段表单 → 前端校验 → 复用 post 的 CSRF 流程 → 201 后 GET 首页。201 后读取失败仍保留保存成功提示，重试只 GET。400/403/409/503 保留草稿，字段错误聚焦对应输入。

子组件现通过 busy 向独立回顾页传递状态。问题加载、草稿、保存或结果不确定时禁用页面返回入口；取消新增不请求写入，恢复按钮焦点。函数入口同时防止重复提交。详情的轮次编辑/删除确认期间禁止进入回顾页。

响应丢失时保留草稿并禁止再次保存。点击“重新加载问题并核对”只 GET 首页，也可在不确定状态翻问题页；读取失败继续锁定。用户查看记录后点击“已核对问题，恢复操作”结束本次草稿，不自动再次添加，也不自动断言这条记录由本次请求创建。

1. 重启后端、刷新前端；选择专用虚构岗位，新增两轮面试。每轮右侧应有“面试回顾”，进入各自页面后无问题显示“无面试过程记录”和“添加记录”。

3. 刷新回顾页后内容保留；返回原轮次，再进入第二轮不能看到第一轮的问题。取消新增不保存，问题草稿期间页面返回入口禁用。
4. 可选新增至 11 条，验证每页 10 条、上一页/下一页问题，最新保存回首页。问题页码与轮次页码分别显示。
